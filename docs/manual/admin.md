# TYPA 管理者マニュアル

本マニュアルは、Admin権限を持つ人事・総務などの管理担当者を対象としています。社員の権限・等級・評価者の設定、等級と共通目標の管理、招待コードの発行、評価期間と評価基準の設定、全社の評価進捗の確認、導入時のデータ取込について説明します。また、通常の操作では変更できない評価シートを修正・状態変更・削除する遡及処理、監査ログの確認方法、セキュリティ検証の内容と対象範囲を説明します。

自身の評価シートの記入方法については「利用者マニュアル」、部下の評価方法については「評価者マニュアル」を参照してください。

## 管理者が利用できる機能

| 画面                               | Admin権限で利用できる管理機能                                                                                                                                                          |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 評価シート                         | 全社の評価進捗と最終評価を一覧で確認し、各シートの内容を読み取り専用で閲覧できます。一覧のPDF出力も可能です                                                                            |
| 社員マスタ                         | 権限・ログイン保持・等級・一次評価者・二次評価者の変更、招待コードの発行、登録の取り消し、利用の停止・再開ができます                                                                   |
| 等級・共通目標（ユーザーメニュー） | 等級の追加・変更・削除、等級ごとの共通目標の選択、共通目標（共通評価の項目・説明・重み）の追加・変更・削除ができます                                                                   |
| 設定（ユーザーメニュー）           | 評価期間の追加（通年・半期・四半期）・開始・締め、評価点の配点、チャレンジ目標数、通知方法（アプリ内通知・メール）の設定ができます                                                     |
| 導入処理（ユーザーメニュー）       | 社員の仮登録（初期ユーザ）と、実施中の評価期間への目標・共通評価・点数のCSV一括取込ができます                                                                                          |
| 遡及処理（ユーザーメニュー）       | 締め済みの評価期間のシートを、理由を記録して修正できます。すべての評価期間で、通知を送信せずにシートの状態変更・削除ができます。実施中の評価期間では、シート作成時の等級も変更できます |
| 監査ログ（ユーザーメニュー）       | 社員マスタの変更、シートの状態遷移、遡及処理、データ取込、等級と共通目標の変更について、操作者・日時・操作内容を確認できます                                                           |
| セキュリティ（ユーザーメニュー）   | リリース前にCIで実施するセキュリティ検証の内容と、検証の対象外となる範囲を確認できます                                                                                                 |

次の操作は、Admin権限でも実行できません。

- 実施中の評価期間において、自身が本人・評価者ではないシートの内容を変更すること。全社の一覧から開いたシートは閲覧専用です。
- 締め済みの評価期間を再度開始すること。締め後に修正が必要な場合は、[遡及処理](#9-遡及処理締め後修正状態変更削除)で項目ごとに修正します。
- 画面から氏名・社員番号を変更すること。変更はシステム担当者がデータベースで行います。社員の追加は、[導入処理の「初期ユーザ」](#初期ユーザ社員の仮登録)から実施できます。
- 等級や共通目標の変更を、作成済みのシートに反映すること。シートには、作成時の共通目標が保持されます（[等級と共通目標](#等級と共通目標)）。

## 1. 1期の運用の流れ

評価は、評価期間ごとに実施します。通年の場合は1期に1回、半期制の場合は上期と下期に1回ずつ、四半期制の場合は年4回、次の手順で運用します。

```
評価期間の開始時：期間を開始 → 社員がシートを作成し、チャレンジ目標と期中目標を提案（送信）
                → 一次評価者が目標を承認（確定）、または差し戻し
評価期間の終了時：社員が達成状況を入力して一次評価を依頼（一次評価者へ自動通知）
                → 一次評価 → 二次評価者を設定している場合は二次評価で最終確定（ランクは得点率から自動判定）
締め：未確定のシートについて所管の部門長に対応を依頼 → 全員の評価確定を確認 → 評価期間を締める
     → （準備中）等級変更の依頼を社員マスタに反映 → 次の評価期間を開始
```

| 時期             | 管理者の作業                                                                                           | 参照                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 期の開始前       | 次の期を追加し、通年・半期・四半期の区分を設定します                                                   | [6](#6-評価期間)                                       |
| 評価期間の開始時 | 準備中の評価期間を開始します                                                                           | [6](#6-評価期間)                                       |
| 期中             | 新入社員などを仮登録し、招待コードを配付します。登録や利用停止に関する問い合わせに対応します           | [3](#3-招待コード)・[4](#4-登録とアカウントのトラブル) |
| 評価期間の終了時 | 全社の一覧で未確定のシートを確認し、所管の部門長に対応を依頼します。二次評価待ちのシートも確認対象です | [5](#5-全社の評価シート)                               |
| 締め             | 全員の評価確定を確認し、実施中の評価期間を締めます。次の評価期間は準備中になります                     | [6](#6-評価期間)                                       |
| 準備中           | 被評価者からの等級変更依頼を社員マスタに反映し、評価者の変更も完了させます                             | [2](#2-社員マスタ)                                     |
| 締め後           | 評価に誤りが判明した場合は、遡及処理で修正します                                                       | [9](#9-遡及処理締め後修正状態変更削除)                 |

導入時は、[導入処理](#8-導入処理データ取込)で、実施中の評価期間に既存の目標などを取り込むことができます。

## 2. 社員マスタ

画面上部の「社員マスタ」を開きます。上段に自身の情報、下段に社員一覧が表示されます。一覧の設定値は、選択すると即時に保存されます。

![社員マスタ（Admin の画面）](admin/02-employees.png)

社員一覧は、一次評価者の社員番号 → 二次評価者の社員番号 → 本人の社員番号の昇順に表示されます。評価者が未設定の社員は、各グループの末尾に表示されます。

一覧上部の「全員」「自分の担当」「未設定あり」で、表示対象を切り替えられます。期初には「未設定あり」を選択し、等級や評価者の設定漏れがないか確認してください。

### 権限

| 権限     | 利用できる機能                                                             |
| -------- | -------------------------------------------------------------------------- |
| Admin    | 本マニュアルで説明するすべての管理操作を実行できます                       |
| Reviewer | 社員マスタで全社員の等級・評価者と評価構造を閲覧できます。変更はできません |
| Employee | 社員マスタで自身の情報のみ閲覧できます                                     |

評価者に設定できるのは、Admin権限またはReviewer権限の利用者、およびキャリアコースが「役員」の社員です。それ以外のEmployee権限の社員には、「部下の評価」は表示されません。

利用可能な登録済みのAdminが1名もいなくなる変更（最後のAdminの権限変更・利用停止）はできません。管理業務を引き継ぐ場合は、先に後任者へAdmin権限を付与し、ログインできることを確認してから変更してください。

### ログイン

| 設定値                       | 内容                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| 閉じたらログアウト（初期値） | アプリを閉じるとログアウトします。共有PCを利用する社員には、この設定を適用してください |
| 保持する                     | アプリを閉じてもログイン状態を保持します。専用PCを利用する社員にのみ設定してください   |

### 等級

等級によって、評価シートの共通評価の項目が決まります。変更後の等級は、**新規に作成するシート**に適用されます。作成済みのシートの等級・評価項目は変更されません。昇級に伴う設定変更は、社員が次の評価期間のシートを作成する前に完了させてください。等級の追加や等級ごとの共通目標の設定は、[等級と共通目標](#等級と共通目標)で行います。

### 一次評価者・二次評価者

氏名・社員番号で検索し、評価者を選択します。二次評価者を指定しない選択肢には、次の2種類があります。

| 二次評価者                 | 内容                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------ |
| 未設定                     | 二次評価者が設定されていない状態です。二次評価を実施できないため、評価は完了しません |
| なし（一次評価が最終評価） | 二次評価を実施せず、一次評価者が最終評価を確定します                                 |

評価者の変更は、実施中の評価期間の**未確定のシート**に反映されます。評価確定済みのシートには、評価を実施した評価者の情報が保持されます。

### 役員

コース区分が「役員」の社員は、権限とログイン設定のみ変更できます。等級・評価者は管理対象外です。評価構造では、評価者としてのみ表示されます。

## 3. 招待コード

社員の新規登録には、管理者が発行する招待コードが必要です。招待コードはシステムが自動生成します。

### 一括発行（導入時・期初）

一覧上部の「招待コードを一括発行」をクリックし、対象を選択して「まとめて発行」をクリックします。利用停止中・登録済みの社員は対象外です。

- **発行済みの社員を除く**（初期選択）：コードが未発行または期限切れの社員に発行します。有効期限内のコードは引き続き利用できます。
- **発行済みの社員も含めて新しく発行する**：有効期限内のコードも再発行します。配付済みのコードと登録途中のトークンは無効になります。新しいコードを本人に配付してください。

![招待コードの一括発行対象の選択](admin/04-bulk-invitation-options.png)

「一覧をコピー」で表示中の一覧をコピーし、表計算ソフトに貼り付けて印刷するなどの方法で、**本人に個別に**配付してください。

![招待コードの一括発行](admin/04-bulk-invitations.png)

### 個別発行・再発行

未登録の社員の行で「招待コード」をクリックすると、対象者のコードが表示されます。

![招待コードの個別発行](admin/05-invitation.png)

| 項目                 | 内容                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| 有効期限             | 発行から7日間です。期限切れの場合は再発行してください                                              |
| 利用回数             | 1回限りです。登録が完了すると無効になります                                                        |
| 再発行               | 発行済みのコードは無効になります                                                                   |
| 表示を閉じた後の確認 | コードは再表示できません。閉じる前にコピーまたは記録してください。紛失した場合は再発行してください |

## 4. 登録とアカウントのトラブル

社員一覧の右端の「登録」列で、登録状態（未登録・登録済み・利用停止中）の確認と、各種操作を行います。

| 問い合わせ・対応事項                       | 操作                                                                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| パスワードを忘れた場合                     | 「取消」で登録を取り消し、招待コードを発行して本人に配付します。本人が新規登録を再度行います。評価データは保持されます       |
| 退職・休職に伴い利用を停止する場合         | 「利用停止」を選択します。ログイン中でも閲覧・保存ができなくなり、新規登録もできません。評価データとアカウントは保持されます |
| 復職に伴い利用を再開する場合               | 「利用再開」を選択します。以前の社員番号とパスワードでログインできます。未登録の社員には招待コードを発行してください         |
| 招待コードを利用できない場合               | 有効期限切れ・使用済み・再発行済みの可能性があります。コードを再発行してください                                             |
| 共有PCで前の利用者のログイン状態が残る場合 | 対象社員の「ログイン」を「閉じたらログアウト」に設定してください                                                             |
| 社員番号が見つからないと表示される場合     | 社員マスタに登録がなければ、導入処理の「初期ユーザ」で仮登録した後、招待コードを配付してください                             |

登録をやり直す場合は「取消」、利用を停止する場合は「利用停止」を選択します。いずれの場合も、評価データは削除されません。利用停止を解除してもログイン保持の設定は元に戻らないため、必要に応じて再設定してください。

## 5. 全社の評価シート

Admin権限の場合、「評価シート」の一覧下部に「全社の評価シート」が表示されます。上部の帯には、選択した評価期間の段階別のシート件数が表示されます。帯の下にある件数をクリックすると、該当する段階に絞り込めます。再度クリックすると、絞り込みが解除されます。

![全社の評価シート](admin/01-overview.png)

- 一次評価者・二次評価者・最終評価（評価点とランク）を一覧で確認できます。
- 行をクリックすると、対象のシートが開きます。下書きを含むすべての段階で、目標・一次評価・二次評価・総評を閲覧できます。入力・送信・確定はできません。画面には「Admin として閲覧しています」と表示されます。
- 自身が本人・評価者であるシートは、Admin権限であっても、その立場に応じた閲覧範囲が適用されます。自身のシートの確定前の点数は閲覧できません。
- 行ごとのPDF出力には対応していません。「一覧をPDF出力」で一覧を出力してください。PDFには、段階ごとのランクと総評も記載されます。
- 締め後に遡及処理で修正したシートは、評価者のシートとPDFに「締め後修正」として赤字で表示されます。
- シートを作成していない社員は、この一覧には表示されません。未作成の社員は、評価者の「部下の評価」画面で、状態が「未作成」の行から確認できます。

### 評価構造

社員マスタの「評価構造」に切り替えると、左から「二次評価者（最終評価）→ 一次評価者 → 評価される社員」の順に、評価の流れが図示されます。点線の枠は、評価者が未設定であることを示します。社員名をクリックすると、リストで対象社員の設定を開きます。

![評価構造](admin/03-structure.png)

## 6. 評価期間

画面右上のユーザーメニューから「設定」を開きます。設定の表示・変更は、Admin権限でのみ可能です。

### 期と評価期間

**期**は、「26期」などの年度を表します。期は、通年で1つの**評価期間**とするか、半期（上期・下期）や四半期に分割して複数の評価期間を設定します。分割した評価期間はそれぞれ独立しており、シートの作成・評価・締めは評価期間ごとに行います。上期と下期の点数を合算して、期の点数を算出する機能はありません。

| 用語         | 意味                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 当期         | 実施中の評価期間が属する期の、すべての評価期間です。半期制の場合は、上期と下期の両方を含みます                   |
| 前の評価期間 | 対象の評価期間の開始前に終了した、直近の評価期間です。下期の場合は当期の上期、上期の場合は前期の下期に該当します |

評価期間の状態は「未開始 → 準備中 → 実施中 → 締め済み」の順に進み、前の状態には戻せません。実施中の評価期間を締めると、未開始の評価期間のうち開始日が最も早い期間が「準備中」になります。**次の評価期間は、自動では開始されません。** 準備中は、評価シートを作成できません。**同時に実施できる評価期間は1つまで**で、シートの作成・記入・評価・確定は、実施中の評価期間でのみ可能です。締め済みの評価期間では、通常の操作は閲覧とPDF出力に限られます。

![評価期間](admin/06-periods.png)

### 期を追加する

1. 「期の名前」（例：26期）、開始日、終了日を入力します。
2. 「区切り」で、通年・半期（上期・下期）・四半期を選択します。下部に、追加される評価期間の名称と日付が表示されます。
3. 必要に応じて「評価が確定していなくても締められる」をオンにします（[未確定のシートがある場合の締め設定](#評価が確定していなくても締められる評価期間)）。
4. 「追加する」をクリックします。

評価期間は、開始日から6か月ごと（四半期の場合は3か月ごと）に分割され、最後の評価期間の末日は期の終了日となります。たとえば3月23日開始の期では、上期は3月23日〜9月22日、下期は9月23日〜期の終了日です。各期間の境界日は自動計算されます。期間が短く、指定した区分に分割できない場合は、その旨が表示されます。

| 操作 | 方法・条件                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------ |
| 変更 | 行の「編集」から、期の名称・日付・締め設定を変更できます。上期・下期などの区分は変更できません   |
| 削除 | 評価シートが1件もない評価期間のみ削除できます。削除は取り消せません                              |
| 締め | 実施中の評価期間の「この期間を締める」を選択します。次の評価期間は準備中になります               |
| 開始 | 準備中の評価期間の「この期間を開始する」を選択します。実施中の評価期間がある場合は開始できません |

### 締める・開始する

評価期間の締めと開始は、それぞれ個別に操作します。

1. 実施中の評価期間の「この期間を締める」をクリックします。確認画面の注意事項を確認し、「締める」をクリックします。
2. 次の評価期間が「準備中」になります。この間に、被評価者からの依頼に基づく等級変更と、評価者の見直しを社員マスタで完了させます。
3. 準備中の評価期間の「この期間を開始する」をクリックし、確認画面で再度「この期間を開始する」をクリックします。

![評価期間の締め確認](admin/07-period-switch.png)

![評価期間の開始確認](admin/17-period-start.png)

- 実施中の評価期間に**未確定のシートが残っている場合は、締めることができません**。ただし、次節の設定を適用した評価期間を除きます。全社の一覧ですべてのシートが「評価確定」になっていることを確認し、未確定のシートがあれば所管の部門長に対応を依頼してください。
- 締め後は、その評価期間のシートを通常の操作で変更できなくなります。未作成の社員も、新たにシートを作成できません。
- **締め済みの評価期間は、再度開始できません。** 締める前に、確認画面の内容を確認してください。締め後に修正が必要な場合は、[遡及処理](#9-遡及処理締め後修正状態変更削除)で項目ごとに修正します。
- 開始できるのは、準備中の評価期間のみです。実施中の評価期間がある場合や、準備中の期間を省略して後続の期間を開始する場合は、開始できません。
- 次の評価期間のシートは自動作成されません。開始後に、社員が各自「新規作成」から作成します。シートの等級は作成時点で固定されるため、等級変更は評価期間の開始前に完了させてください。
- 締めと開始の操作は、操作者・日時とともに監査ログ（種類「評価期間」）に記録されます。
- 利用中の社員の画面には、画面を開き直した時点で反映されます。

### 評価が確定していなくても締められる評価期間

「評価が確定していなくても締められる」をオンにした評価期間は、未確定のシートが残っていても締めることができます。正式運用前の評価期間に目標のみを取り込み、評価を実施せずに締める場合などに利用します。

- 締めたシートは、締め時点の状態（下書きなど）で保持されます。
- 評価者は、締め後のシートを下書きの状態でも閲覧できます。
- 未確定のシートもPDFに出力できます。PDFの点数・ランク・評価者コメントは `***` と表示されます。

## 7. 評価の基準

### 評価点の配点

評価点は100点満点です。チャレンジ目標と共通評価にそれぞれ何点を配分するかを設定します。一方の配点を変更すると、他方には残りの点数が設定されます。「配点を保存する」をクリックして保存します。

![評価点の配点](admin/08-allocation.png)

- 変更は、**未確定の評価シート**の評価点と見込みランクに反映されます。確定済みのシートと、確定済みの一次評価ランクは変更されません。
- 配点は、全評価期間に共通する設定です。期中に変更すると見込みランクにも影響するため、期初に設定し、期中の変更は避けてください。

評価ランクは、評価点（100点満点）から自動判定されます。基準は、95点以上がS、90点以上がA、80点以上がB+、60点以上がB、50点以上がB-、40点以上がC、40点未満がDです。

### チャレンジ目標の数

1枚の評価シートに設定できるチャレンジ目標数の上限を指定します。目標は最低1件必要です。上限を引き下げた場合、目標数が新しい上限を超える未確定のシートは、目標を削減するまで送信・確定できません。

![チャレンジ目標の数](admin/09-max-goals.png)

### 等級と共通目標

画面右上のユーザーメニューから「等級」「共通目標」を開きます。Admin権限でのみ利用できます。共通目標は、評価シートの共通評価に表示する項目（項目名・説明・重み）をまとめたものです。等級ごとに適用する共通目標を選択します。同じ項目で評価する等級には、同じ共通目標を設定します。

**変更は、作成済みの評価シートには反映されません。** 評価シートには、作成時の等級に設定されていた共通目標が保持されます。等級に適用する共通目標を変更した場合も、共通目標の項目を修正した場合も、変更は**新規に作成するシート**にのみ反映されます。

- 作成済みのシートで使用されている共通目標の項目を修正して保存すると、**新しい版**が作成されます。その共通目標を使用する等級には新しい版が適用され、作成済みのシートには旧版が保持されます。旧版は画面に表示されません。名称のみを変更した場合は、新しい版は作成されません。共通目標の名称は、評価シートには表示されません。
- 修正内容を作成済みのシートにも適用する必要がある場合は、対象のシートを再作成する必要があります。対象等級の社員全員に再作成が必要となる場合があります。再作成の対象シートは、[遡及処理](#9-遡及処理締め後修正状態変更削除)の「削除」から削除できます。新しい評価期間の開始前に修正を完了しておくことで、再作成を回避できます。
- 等級の名称を変更した場合は、作成済みのシートにも新しい名称が表示されます。

#### 等級

一覧には、等級ごとの共通目標・社員数・作成済みシート件数が表示されます。下部のフォームから等級を追加し、「編集」で名称と共通目標を変更します。作成済みのシートがある等級の共通目標を変更する場合は、確認メッセージが表示されます。

- 社員が所属する等級と、評価シートの記録で使用されている等級は削除できません。社員の等級は、[社員マスタ](#等級)で変更します。

#### 共通目標

「編集する共通目標」で対象を選択し、名称と項目を編集して「保存する」をクリックします。新規作成する場合は、「共通目標を追加」を選択します。

| 項目   | 入力条件                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------- |
| 名前   | 50文字以内です。管理用の名称であり、評価シートには表示されません                                |
| 項目名 | 100文字以内です。同一の共通目標内では重複できません。項目数は1〜30件です                        |
| 説明   | 1000文字以内です。省略できます                                                                  |
| 重み   | 1〜10の整数です。共通評価の得点は、各項目の評価点（1〜4）に重みを乗じて合計し、配点に換算します |

- 画面上部には、対象の共通目標を使用する等級と、作成済みシートの件数が表示されます。
- 等級に設定されている共通目標と、評価シートの記録で使用されている共通目標は削除できません。

他のAdminが同時に編集していた場合は、保存されず、再読み込みを求めるメッセージが表示されます。変更前後の内容は、監査ログに記録されます。

### 通知

目標の送信時と一次評価の依頼時は一次評価者へ、目標の確定・差し戻し時は本人へ、一次評価の確定時は二次評価者へ通知します。通知方法は、**アプリ内通知**または**メール**のいずれか一方を選択します。

![通知](admin/10-smtp.png)

#### 通知の方法

| 方法                 | 通知先・表示場所                                         | 選択条件                                                         |
| -------------------- | -------------------------------------------------------- | ---------------------------------------------------------------- |
| アプリ内通知（既定） | 画面上部のベルに未読件数が表示されます                   | 常時選択できます                                                 |
| メール               | 評価者が新規登録時に確認したメールアドレスに送信されます | 「メールの送信設定」で送信テストが成功している場合に選択できます |

通知方法は、選択すると即時に切り替わります。アプリ内通知は状態変更と同時に記録されるため、送信失敗や再送の処理はありません。評価が次の段階に進んだ依頼は自動で既読になり、一次評価者が要修正として差し戻した依頼は取り下げられます。異動などで評価者が変更された場合は、対応待ちの依頼が新しい評価者に通知されます。

#### メールの送信設定

通知メールに使用するメールサーバーと送信元を設定します。**設定は、送信テストが成功した場合にのみ保存されます。** 送信を確認していない設定では、通知方法としてメールを選択できません。

| 項目                 | 内容                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------- |
| SMTP ホスト          | 送信に使用するメールサーバーを指定します                                                                |
| ポート               | **465（TLS）**を指定します。587および25は使用できません                                                 |
| 送信元メールアドレス | 通知メールの差出人を指定します                                                                          |
| パスワード           | 保存後は表示されません。変更時のみ入力します。SMTPホストまたは送信元を変更する場合は、再入力が必要です  |
| 宛先メールアドレス   | 送信テストの宛先を指定します。この値は保存されません                                                    |
| 通知パターン         | 送信テストの文面を選択します。目標送信・目標確定・目標の差し戻し・一次評価依頼・一次評価確定の5種類です |

1. 各項目を入力し、「テストメールを送って保存する」をクリックします。
2. 入力した設定でテストメールを送信します。件名には「送信テスト」と表示され、サンプルの社員・評価期間を使用した、通常の通知と同じ文面が送信されます。
3. 送信が成功すると設定が保存され、「送信テスト済み（日時）」と表示されます。以降、通知方法として「メール」を選択できます。

送信に失敗した場合は、メールサーバーの応答が「（詳細: …）」として表示され、設定は保存されません。パスワードは表示されません。たとえば、`HandshakeFailure` は、メールサーバーの暗号化方式が古いことによる接続失敗を示します。

送信済みの通知メールが届かない場合は、迷惑メールフォルダーや共有メールの受信箱を確認してください。該当メールが見つからない場合は、メールサーバー側の配送記録を確認してください。

## 8. 導入処理（データ取込）

画面右上のユーザーメニューから「導入処理」を開きます。導入時に必要な初期設定・データ取込を行う画面です。Admin権限でのみ利用できます。

![導入処理](admin/11-setup.png)

### 初期ユーザ（社員の仮登録）

社員マスタに新しい社員を追加します。仮登録の段階では「未登録」となり、ログインできません。

1. 「初期ユーザ」を開き、社員番号・氏名・キャリアコース・等級を入力します。一次評価者・二次評価者の設定は任意で、後から社員マスタで設定できます。キャリアコースが「役員」の場合は、評価者を選択しません。
2. 「仮登録する」をクリックし、確認画面で内容を確認して、再度「仮登録する」をクリックします。**社員番号と氏名は、登録後に画面から変更できません。** 確定前に入力内容を確認してください。
3. 社員マスタで対象社員の[招待コード](#3-招待コード)を発行し、本人に配付します。

社員番号はログインIDとして使用するため、半角英数字・ハイフン・アンダースコアのみ使用できます。全角で入力した場合は、半角に変換されます。大文字・小文字のみが異なる社員番号は、重複として扱われ、登録できません。初期権限はEmployeeです。

### データ取込

「データ取込」では、**実施中の評価期間**に対して、目標・共通評価・点数をCSVで一括取込できます。取り込んだシートは下書きとして作成され、通知メールは送信されません。

1. 「目標のテンプレート」「共通評価のテンプレート」を保存します。テンプレートには、取込対象となる社員の社員番号・氏名、および目標番号・共通評価の項目が含まれます。目標を送信済みの社員は含まれません。
2. Excelなどで本文と点数を入力して保存します。「CSV UTF-8」「CSV」のいずれの保存形式にも対応しています。
3. 「目標」「共通評価」の欄でファイルを選択し、「内容を確認」をクリックします。いずれか一方のみの取込も可能です。この段階では、データは保存されません。
4. 確認結果に問題がなければ「取り込む」をクリックし、確認画面で再度「取り込む」をクリックします。

| 入力項目・条件          | 内容                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 変更不可の列            | 社員番号・目標番号・項目IDは変更しないでください。氏名と項目名は、対象に誤りがないことを確認するために使用します                                                                     |
| 点数                    | 1〜4の数値、または空欄とします                                                                                                                                                       |
| 期中目標が2件以上の場合 | 同じ社員番号・目標番号の行を追加し、1行につき1件入力します。最大4件で、ファイルの行順に取り込まれます。チャレンジ目標・点数は最初の行に入力し、2行目以降は空欄または同じ内容とします |
| 期中目標がない場合      | 「達成状況」列には、チャレンジ目標に対する達成状況を入力します。期中目標がある場合は、期中目標の行ごとに達成状況を入力します                                                         |
| 未入力の行              | 取込対象外です                                                                                                                                                                       |
| 1行以上入力した社員     | 実施中の評価期間の目標、または共通評価が、ファイルの内容で置き換えられます                                                                                                           |

**エラーが1件でもある場合、データは取り込まれません。** エラーは、ファイル・行番号・内容の一覧で表示されます。行番号は、見出しを1行目とするExcelの行番号に対応します。ファイルを修正して再選択し、再度確認してください。

![データ取込のエラー](admin/12-import-errors.png)

エラーがない場合は、対象社員数、新規作成するシートと内容を置き換えるシートの件数、および目標と共通評価の件数が表示されます。

![データ取込の確認](admin/13-import-ready.png)

## 9. 遡及処理（締め後修正・状態変更・削除）

画面右上のユーザーメニューから「遡及処理」を開きます。通常の操作では変更できないシートに対し、理由を記録したうえで修正・状態変更・削除を行います。Admin権限でのみ利用できます。

1. 左側の「評価期間」で対象期間を選択します。期間名の後ろには、（実施中）（締め済み）などの状態が表示されます。社員番号・氏名による絞り込みも可能です。
2. 一覧からシートを選択すると、右側に対象のシートが開きます。
3. 上部の切り替えで、実行する操作を選択します。

| 操作         | 対象の評価期間 | 内容                                                                                                                       |
| ------------ | -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 値を直す     | 締め済みのみ   | 目標・点数・コメントを修正します。本人と評価者のシートに「締め後修正」として赤字で表示されます                             |
| 状態を変える | すべて         | 承認や通常の進行条件を省略して、任意の状態に変更します。通知は送信されません                                               |
| 等級を変える | 実施中のみ     | シート作成時の等級を変更します。共通評価の入力内容（点数・コメント）はすべて削除され、復元できません。通知は送信されません |
| 削除する     | すべて         | シートと、それに関連する目標・評価・修正記録を削除します。削除は取り消せません。通知は送信されません                       |

4. 画面下部の「理由」（必須・500文字以内）を入力し、確認ボタンをクリックします。
5. 確認画面で対象と内容を確認し、実行します。

未保存の入力内容がある状態で、別のシート・期間・操作に切り替えようとすると、入力内容を破棄するかどうかの確認メッセージが表示されます。

![遡及処理](admin/14-retroactive.png)

![遡及処理の確認](admin/15-retroactive-confirm.png)

### 値を直す

| 修正可能な項目 | 内容                                                   |
| -------------- | ------------------------------------------------------ |
| チャレンジ目標 | チャレンジ目標・期中目標・達成状況・一次評価・二次評価 |
| 共通評価       | 一次評価・二次評価・一次評価者コメント                 |
| 総評           | 一次評価者の総評・二次評価者の総評                     |

- 締め前の評価期間では、本人と評価者が通常のシート画面で修正します。「値を直す」は選択できません。
- 変更した欄は赤色で表示されます。点数は1〜4で入力します。二次評価者を設定しないシートには、二次評価の入力欄はありません。
- 評価確定済みのシートの点数を修正すると、確定時の配点に基づいて評価点とランクが再計算されます。
- 現在と同一の内容では修正を保存できません。修正前後の値・理由・日時が記録され、修正は取り消せません。修正履歴は、画面下部の「このシートの修正の記録」で確認できます。
- 本人と評価者のシート、およびPDFには、「締め後修正」として赤字で表示されます。修正内容は、該当項目の閲覧権限を持つ利用者にのみ表示されます。閲覧範囲は、評価内容と同じです。

### 等級を変える

人事発令の登録漏れなどにより、シート作成時の等級に誤りがある場合に使用します。

- 変更できるのは、実施中の評価期間に属し、一次評価が確定する前（一次評価待ちまで）のシートに限られます。一次評価が確定済みの場合は、先に「状態を変える」で一次評価待ち以前の状態に戻します。
- 等級変更に伴い、共通評価の項目が変更されます。**共通評価の入力済みの点数とコメントはすべて削除され、復元できません。** 評価者には、新しい等級の項目で共通評価を再実施するよう依頼してください。
- チャレンジ目標・期中目標・達成状況・チャレンジ目標の点数・総評・状態・評価者は変更されません。
- 社員マスタの等級は変更されません。次の期のシートにも新しい等級を適用する場合は、社員マスタの等級も変更してください。
- 通知は送信されません。変更前後の等級・削除された点数とコメント・理由は、監査ログに記録されます。

### 状態を変える・削除する

- 状態は進行順に表示され、現在の状態は選択できません。記入済みの内容や点数は保持されますが、確定済みの評価点とランクは解除されます。「評価確定」に変更した場合は、その時点で再計算されます。
- アプリ内通知・メールともに送信されません。操作者・対象・変更前後の状態・理由は、監査ログに記録されます。削除時は、削除前の目標・評価・修正記録も監査ログに保存されます。
- 確認中にシートの状態が変更された場合は、処理は実行されません。再読み込み後に操作してください。

## 10. 監査ログ

画面右上のユーザーメニューから「監査ログ」を開きます。社員マスタの変更、シートの状態遷移、遡及処理、データ取込、等級と共通目標の変更について、操作者・日時・対象・操作内容を新しい順に確認できます。Admin権限でのみ利用できます。

監査ログは、操作の実行と同時にデータベースに記録されます。ログの記録に失敗した場合、その操作は実行されません。アプリから監査ログを変更・削除することはできず、この画面は閲覧専用です。

![監査ログ](admin/16-audit-log.png)

| 種類             | 記録内容                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 社員・アカウント | 権限・評価者・等級・ログイン保持の変更、利用の停止・再開、登録と登録の取り消し、招待コードの発行、事前登録 |
| 評価の進行       | シートの状態遷移（目標の送信・確定・差し戻し、一次評価の依頼・確定、評価の確定）と操作者                   |
| 遡及処理         | 締め後修正・状態変更・削除・作成時の等級変更と、その理由                                                   |
| 評価期間         | 評価期間の締め（評価確定済み・未確定のまま締めたシートの件数）と開始                                       |
| 取込             | データ取込の対象評価期間と件数                                                                             |
| 等級・共通目標   | 等級と共通目標の追加・変更・削除と、変更前後の内容。新しい版を作成した場合は、旧版を保持するシートの件数   |

- 遡及処理の記録には、朱色の検印が表示されます。「訂」は締め後修正、「特」は状態変更、「削」は削除、「級」は等級変更を示します。検印が付いた記録から、通常の手順によらない操作と、その理由を確認できます。
- 変更前の値は消し線、変更後の値は太字で表示されます。評価者・等級・権限は、IDではなく名称で表示されます。
- 「対象の社員」を選択すると、その社員の社員マスタの変更と、シートの記録に絞り込まれます。「操作した人」では、選択した利用者のアカウントで実行された操作に絞り込めます。「期間」の終了日は、当日の終了時刻までを含みます。
- 現存するシートは「シートを開く」から閲覧できます。削除済みのシートは開けませんが、削除前の内容を「記録の原文」で確認できます。削除済みのシートの状態遷移の記録は、「対象の社員」では検索できません。種類と期間で検索してください。
- 1回につき100件ずつ読み込みます。それ以前の記録は、一覧下部の「さらに前の記録を読み込む」から確認できます。
- パスワード、メールアドレス、招待コードは記録されません。

## 11. セキュリティ

画面右上のユーザーメニューから「セキュリティ」を開きます。TYPAのリリース前に、実際の認証機能・データベース・APIを対象に実施する、攻撃や不正操作に関する検証内容を確認できます。Admin権限でのみ利用できます。社内への説明や、監査・情報システム部門への回答資料として利用できます。

| 画面内の節                 | 内容                                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 「配布の前に毎回通す検査」 | CIで毎回実施する検証です。1件でも失敗した場合、その版はリリースされません。検査IDとOWASP ASVSの要件番号が記載されています |
| 「人事評価ならではの不正」 | 他の利用者のシートの不正閲覧、二次評価の点数の不正変更、締め後の直接変更などを防止する仕組みを説明しています              |
| 「よく知られた攻撃」       | XSS・SQLインジェクション・CSRFなどへの対策と、確認方法（毎回の検証・設定の検査・設計による防止）を説明しています          |
| 「変更そのものを見張る」   | データベースの権限台帳の照合や依存ライブラリの検査など、改修によるセキュリティ対策の欠落を防ぐ仕組みを説明しています      |
| 「担保していない範囲」     | 検証の対象外となる事項と、本番環境の認証設定やメールサーバーの選定など、運用で対応が必要な事項を説明しています            |

- 「担保していない範囲」に記載された事項は、本番環境の設定・運用で対応してください。特に、本番環境のSupabase Authにおけるパスワードの長さと漏えいしたパスワードの拒否設定、および通知用メールサーバーの選定を確認してください。
- この一覧は、OWASP ASVS 5.0.0から選定した要件に対する回帰検証の内容です。ASVSの認定や、全項目への適合を示すものではありません。

## 12. よくある質問

| 質問                                                               | 回答                                                                                                                                                                                         |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発行した招待コードを再確認できますか                               | 表示を閉じたコードは再表示できません。「招待コード」から再発行してください。以前のコードは無効になります                                                                                     |
| Reviewer権限で評価者を変更できますか                               | 評価者・等級・権限の変更は、Admin権限でのみ可能です                                                                                                                                          |
| 確定した評価を訂正するにはどうすればよいですか                     | 評価期間の締め後に、[遡及処理](#9-遡及処理締め後修正状態変更削除)で項目ごとに修正します。修正内容は理由とともに記録され、本人と評価者に表示されます                                          |
| 誤って評価期間を締めた場合、元に戻せますか                         | 締め済みの評価期間は再度開始できません。シートの修正が必要な場合は遡及処理を利用し、以降の記入・評価は次の評価期間で行ってください                                                           |
| 次の評価期間を開始できません                                       | 実施中の評価期間に未確定のシートが残っています。全社の一覧で「評価確定」以外を絞り込んで確認してください。評価を実施せずに締める場合は、「評価が確定していなくても締められる」をオンにします |
| 上期と下期の点数を合算して期の評価にできますか                     | 分割した評価期間はそれぞれ独立しており、合算・平均する機能はありません                                                                                                                       |
| データ取込で「目標を送信済みのため、取り込めません」と表示されます | 実施中の評価期間で目標を送信済みのシートは、データ取込で上書きできません。対象社員はテンプレートにも含まれません                                                                             |
| 等級を変更してもシートの評価項目が変わりません                     | 作成済みのシートには、作成時の等級が保持されます。変更は、新規に作成するシートから反映されます                                                                                               |
| 二次評価を実施しない社員は、どのように設定しますか                 | 二次評価者を「なし（一次評価が最終評価）」に設定します。「未設定」のままでは評価が完了しません                                                                                               |
| 社員の氏名や社員番号を変更するにはどうすればよいですか             | 画面からは変更できません。システム担当者に依頼してください                                                                                                                                   |
